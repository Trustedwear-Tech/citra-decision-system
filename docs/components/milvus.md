# Milvus — Deployment Guide

Milvus is the vector database used for RAG (Retrieval-Augmented Generation) — storing and searching document embeddings.

## Requirements

- Milvus 2.4+ (standalone or cluster)
- Dependencies: etcd (metadata), MinIO or S3 (internal storage)
- Collection: `citra` (auto-created by Citra-Service)

## Option A: Zilliz Cloud (Managed Milvus)

1. Create a cluster at [zilliz.com](https://zilliz.com)
2. Get the endpoint and API key
3. Set in `.env`:
   ```env
   MILVUS_URI=https://your-instance.zillizcloud.com
   MILVUS_TOKEN=your-api-key
   MILVUS_COLLECTION=citra
   ```

## Option B: Docker (Single Machine)

The compose file includes Milvus + etcd + an internal MinIO (for Milvus storage only):

```bash
cd infrastructure/compose
docker compose -f docker-compose.base.yml -f docker-compose.milvus.yml \
  --env-file ../../.env up -d
```

This starts:
- **Milvus standalone** on port `19530` (gRPC) and `9091` (HTTP metrics)
- **etcd** (internal, for metadata)
- **MinIO** (internal, for Milvus segment storage — separate from application MinIO)

Default config:
```env
MILVUS_URI=http://localhost:19530
MILVUS_TOKEN=
MILVUS_COLLECTION=citra
```

> **Note**: The MinIO inside the Milvus compose file is for Milvus internal use only. Application file storage uses a separate MinIO or S3 instance (see [object-storage.md](object-storage.md)).

## Option C: Self-Managed Server

Follow the official Milvus installation guide:
- [Milvus Standalone (Docker)](https://milvus.io/docs/install_standalone-docker.md)
- [Milvus Standalone (Binary)](https://milvus.io/docs/install_standalone-docker-compose.md)

Point your Citra services to the remote Milvus:
```env
MILVUS_URI=http://<milvus-host>:19530
MILVUS_TOKEN=
```

## Environment Variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `MILVUS_URI` | Yes | `http://milvus:19530` | Milvus gRPC endpoint |
| `MILVUS_TOKEN` | No | (empty) | API token (required for Zilliz Cloud) |
| `MILVUS_COLLECTION` | Yes | `citra` | Collection name |

## Embedding Configuration

Milvus stores vectors generated by your embedding model. Configure the embedding model in `.env`:

```env
# Cloud embedding provider (shipped default)
EMBEDDING_BASE_URL=https://openrouter.ai/api/v1
EMBEDDING_API_KEY=sk-or-...
EMBEDDING_MODEL=baai/bge-m3
EMBEDDING_DIMENSION=768

# Or any OpenAI-compatible embedding endpoint (e.g. a vLLM server you operate)
EMBEDDING_BASE_URL=http://<your-embedding-host>:8000/v1
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_DIMENSION=1024
```

## Verification

```bash
# Check Milvus health
curl http://localhost:9091/healthz

# Or via gRPC port
curl http://localhost:19530/v2/vectordb/collections/list

# Setup validator
./scripts/setup.sh --check
```

## Backup

Use the [Milvus Backup Tool](https://github.com/zilliztech/milvus-backup):
```bash
# Install
go install github.com/zilliztech/milvus-backup/cmd/milvus-backup@latest

# Backup
milvus-backup create -n my-backup
```
